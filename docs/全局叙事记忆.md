# 全局叙事记忆

## 核心原则

全局记忆不是聊天记录集合，而是版本化叙事事实系统。模型输出只有在通过程序校验和人工审核后，才能进入正式事实。

事实优先级：

1. 作品宪法与用户明确设定。
2. 已审核人物、关系、事件、状态、伏笔和章节。
3. 当前任务相关的历史过程记录。
4. 草案、失败结果和人工退回内容。

第四类内容只用于诊断，不得覆盖前三类事实。

## 记忆结构

每条正式事实包含：

- 稳定事实键。
- 事实版本。
- 主体、关系和内容。
- 来源引用。
- 生效顺序。
- 当前状态。
- 接受时间与接受原因。
- 失效时间与失效原因。

正式事实改变时，旧版本标记为 `superseded`，不会直接删除。Agent 默认只能检索 `active` 事实。

过程记录状态：

- `running`：任务执行中。
- `proposed`：等待审核的草案。
- `accepted`：人工确认的结果。
- `rejected`：人工退回。
- `quarantined`：执行失败或校验失败。

`rejected` 和 `quarantined` 不会注入普通创作上下文。

## 渐进式检索

每次 Agent 任务按以下顺序取回：

1. 强制注入作品宪法。
2. 根据任务词、人物名、地点和叙事线检索相关事实。
3. 生成指定章节时加载此前三章的时间邻域。
4. 强制加载未回收伏笔。
5. 仅加载少量已接受过程记录。

所有返回事实带记忆 ID 和来源路径，冲突时必须引用来源，禁止擅自选择。

## 持久化

浏览器小说对象保存完整版本历史；服务端 SQLite 保存：

- `narrative_memories`：每本小说的完整记忆快照。
- `narrative_memory_facts`：当前有效事实。
- `narrative_memory_facts_fts`：FTS5 全文检索索引。

数据使用 `username + novel_id` 隔离，禁止不同小说之间共享具体人物、势力、事件或道具事实。

跨小说只能共享抽象创作经验和校验规则，不能共享故事实体。
